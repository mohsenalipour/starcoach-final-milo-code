# Node Workshop

Read package.json and the existing tests before editing source. Prefer the existing test command. When no dependency installation is needed use the bundled Node runtime with `node --test`. Keep tests meaningful: edge cases and behavior, not copies of implementation. Do not change a failing test to hide a regression. Read stdout/stderr and correct the implementation after a real failure. A skill test command is useful while exploring; call the dedicated `verify` tool for the final approved acceptance test.
